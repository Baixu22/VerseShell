## 2. F2 复核：bootstrap 单位确实是「行」，但「有效样本≈25」被高估

**代码事实**：`tools/live_uncertainty.py:176`
`sample = [pairs[rng.randrange(n)] for _ in range(n)]` —— 重抽单位是**行** `(task_id, seed, run_index)`。
该函数 docstring（`:164`）自称 "resampling the (task, seed) cells"，**这句话是误导**：
一个 cell 就是一行，所以它并没有做任务聚类。审计者这条查对了。

**但「同一任务下的 3 个 seed 高度相关」这个前提，实测只对了一半**（方差分析 ICC，25 任务 × 3 seed）：

| 指标 | ICC | 设计效应 | **有效样本量** |
|---|---|---|---|
| log 观察 token 比 D/A | 0.282 | 1.48 | **41.9** |
| 工具调用比 D/A | 0.306 | 1.57 | **42.0** |
| log 观察 token 比 D/A′ | 0.326 | 1.59 | **37.1** |
| 成功率（A 臂） | 0.563 | 2.13 | **35.3** |
| 成功率（D 臂） | 0.456 | 1.91 | **39.2** |
| 工具调用比 D/A′ | 0.078 | 1.15 | 55.0 |

**所以有效样本是 ≈35–42，不是 25。** 审计者「要补的是任务不是 seed」这个处方仍然正确
（补 seed 的设计效应接近 1，性价比极低），但「有效样本接近 25」把问题夸大了约 1.6 倍。

**代价仍然真实且关键**：任务聚类 bootstrap 稳定地把上界抬高（100k 次 × 5 种子，极稳定）：

| 指标 | 行级上界 | 聚类上界 | 门槛 | 后果 |
|---|---|---|---|---|
| 观察 token D/A | 0.8563–0.8571 | **0.898–0.900** | **L2 = 0.90** | **正好压在门槛上** |
| 观察 token D/A′ | 1.3743–1.3774 | 1.555–1.564 | 1.00 | 更远离门槛 |
| 工具比 D/A | — | 0.767–1.353 | 1.00 | 仍跨 1.0 |

**这是本轮复核最要命的一条**：简报 §4.3 把「省 ≥15%（L2）」标成 ✅ 可主张，依据是上界 0.8551 < 0.90。
改成按任务聚类后上界落在 **0.898–0.900**，也就是说**这条声明是在门槛上以 ≤0.002 的余量成立的**，
换一次重抽就可能翻。**L2 不能算「可主张」，只能算「不确定，压在门槛上」。**

### 3.4 附带发现：`acceptance_power.py` 的非劣性表达式有优先级 bug

`tools/acceptance_power.py:279-280`：

```python
diffs = [1.0 if c["verseshell_aci"].get("success") else 0.0
         - (1.0 if c[baseline].get("success") else 0.0) for c in cells.values()]
```

条件表达式优先级低于 `-`，所以它实际等价于
`1.0 if D_success else (0.0 - A_success)` —— **D 成功就记 1.0（不管 A 是否也成功）**。

复算验证：该表达式在 D vs A 上给出分布 `{+1: 62, 0: 6, −1: 7}`、均值 **0.7333**、下界 **0.5864**，
与产物 `acceptance_power.json:70-71` 的 `success_noninferiority_lower_bound: 0.5864`、
`success_mean_diff_D_minus_A: 0.7333` **完全一致**；正确表达式应给出均值 **0.12**、下界 **−0.0085**
（`live_uncertainty.json` 的配对 t 下界 −0.0032）。

**影响**：结论碰巧不变（正确的下界 −0.0032 也 ≥ −0.10 的边界，非劣仍成立），
但产物里那个 **0.5864 是一个无意义的数**，看起来像「巨大的安全余量」，
而真实的余量只有 **0.097**。这条审计没发现。

## 5.3 复核新增：§3.3 的预算纪律只量了「步数上限」，漏了「completion 上限」

简报 §3.3 明确把**两个**预算都写进纪律：

> 任何「每次运行的预算上限」（`max_turns` / `max_tokens`）都必须先证明**没有在不对称地截断某一个臂**。
> **任一侧撞上限 >10% 即视为上限构成约束，必须提高上限重跑**。

但 `tools/three_arm_report.py` 的 `at_cap` 只判 `turns >= max_turns`，**完全没有量 `max_tokens`**。
于是简报 §4.1 那句「**`cap_ok = true`**（三臂 0% 截断）——这是**第一次**预算不构成约束，所以本轮不受 §3.3 污染」
只对**步数**上限成立。把 completion 上限也量上，第 12 轮「定版」是：

| 臂 | 步数上限（旧口径，简报只报这个） | **completion 上限（`finish_reason == "length"`）** |
|---|---|---|
| `raw_shell`（A） | 0/75 = 0% | **8/75 = 11%** |
| `raw_shell_coached`（A′） | 0/75 = 0% | **11/75 = 15%** |
| `verseshell_aci`（D） | 0/75 = 0% | 0/75 = 0% |

**两条都越过 §3.3 的 10% 门槛，而且全部落在裸 shell 一侧。** 这不是学术问题：被
`finish_reason == "length"` 截断的那一轮**不会发出工具调用**，于是整行被记成**普通任务失败**——
所以这个截断**压低的是 A/A′ 的成功率**，也就抬高了「D 成功率更高」的幅度。
换句话说，简报那个 `D−A = +0.12` / `D−A′ = +0.16` 里，有一部分是**预算造成的**，不是接口造成的。

这与 D2 记录的现象是同一类（「上限不是中立参数」），只是第 12 轮只堵了步数那一半。

**已修**：`tools/three_arm_report.py` 现在同时量两个上限（`turn_cap_binding` / `token_cap_binding`），
`cap_ok` 由两者共同决定，`verdict` 会点名是哪一个在约束。用它复算第 12 轮定版，结论是
**`cap_ok = false`** —— 简报 §4.1 的「第一次预算不构成约束」**不成立**。

**顺带**：新一轮 live（tag `tf0100`，2026-09-26）的 seed 42 里方向**反过来了**——A/A′ 的
completion 截断是 0%，而 D 是 **3/25 = 12%**（3 行 `turns=1 / 0 tools / ctok=16384`）。
所以两轮都在违反 §3.3，只是违反在不同的臂上；**两轮的头条对比都不能直接用**。

### 5.3.1 重跑之后：§3.3 第一次真正达标，而头条差距缩到 1/3

`python tools/live_round.py --tag tf0100 --arms with --seeds 42,43,44 --max-turns 20`（用修好的
harness，225 行、`api_error` 0）跑完后，**两个预算都不构成约束**：

| 臂 | 成功 | 步数上限 | **completion 上限** | harness 崩溃 | 工具数 | 观察 token |
|---|---|---|---|---|---|---|
| `raw_shell`（A） | 0.8400 | 0% | **3%** | **0** | 4.35 | 1032.4 |
| `raw_shell_coached`（A′） | 0.8400 | 0% | **7%** | **0** | 4.40 | 723.8 |
| `verseshell_aci`（D） | 0.8800 | 0% | **4%** | **0** | 3.89 | 578.3 |

**这是第一次两个预算都 ≤10%**，所以这一轮才是真正不受 §3.3 污染的样本。
`harness_crash` 三臂全 0（第 12 轮是 A 3、A′ 2），且那个曾让 A 崩溃 3/3 的任务
`typescript_reduce_shared_accumulator_d80f462d` 现在 **A 三个 seed 全 PASS**。

**与第 12 轮定版对比（同一口径，均为任务聚类区间）**：

| 量 | 第 12 轮 | **本轮（tf0100）** |
|---|---|---|
| D−A 成功率 | **+0.12**（16 vs 7） | **+0.04**（6 vs 3） |
| D−A′ 成功率 | **+0.16**（17 vs 5） | **+0.04**（6 vs 3） |
| D/A 观察 token | 0.6853 [0.5509, 0.9061] | **0.5601 [0.4654, 0.6832]** |
| D/A′ 观察 token | 1.0567 [0.7645, 1.5675] | **0.7990 [0.6503, 0.9788]** |
| D/A 工具数 | 1.0074 [0.7667, 1.3527] | **0.8943** |

**三条实质变化**：

1. **成功率优势缩到 1/3**（+0.12/+0.16 → +0.04/+0.04）。这与 §5.3 的判断一致：第 12 轮里 A/A′ 各被
   completion 上限截断 11%/15%，被截断的轮次不发工具调用、直接记失败，所以**压低的是 A/A′**，
   从而**放大了 D 的优势**。把预算修到不构成约束之后，优势掉到 +0.04。
2. **「提示词拉平后 token 优势消失」这条被推翻**：D/A′ 从 1.0567（跨 1.0）变成 **0.7990，上界 0.9788 < 1.0**。
   即在这一轮，**接口相对提示词等量对照也有观察 token 优势**。注意余量只有 0.021，属薄边通过。
3. **D 的工具数从「持平」变成「更少」**（1.0074 → 0.8943）。

**必须同时说清的**：真实 tokenizer 口径仍然相反——总 token D/A = **1.0761 [0.7667, 1.6552]**（跨 1.0）、
D/A′ = **1.2654 [1.0372, 1.613]**（**整个区间在 1.0 之上**）。所以「观察 token 更省」与「总开销更贵」
在本轮**同时成立**，且对 A′ 的那一支比第 12 轮更确定。

**结论**：第 12 轮那份「定版」既受 §3.3 污染（两个臂被 completion 上限截断），又不可复现
（同一 harness、同一任务集、同一端点，头条差距差 3 倍）。这直接支持本报告的总判断：
**单轮结论不得当作定论**。
