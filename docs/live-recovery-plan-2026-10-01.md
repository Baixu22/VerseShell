## 3. R1：让评分反映真实要求

先修 rust_add_unit_test 与 rust_search_and_edit 的新版本，再审查其余仅文本判据的任务。
不在原 v3.0.0 冻结任务上直接修改以重新计算旧成绩。

- 将编译/行为测试纳入必须执行的 success；optional_verify 不再承担实际评分职责。
- add 测试允许等价的有效用例，验证测试确实执行；不能只凭特定字符串或注释判断。
- sum 验证函数在正常、零、负数输入下的行为，允许尾表达式；不要要求某种等价写法。
- 对产物内容精确性任务保留合理的 file_equals/文本契约，不为统一形式而改成复杂框架。

**退出条件**：本次四个控制全部获得正确结论；正确变体通过，错误算子、无测试、注释伪装
等最小变异被拒绝；超时与环境缺失有独立状态；任务/fixture 新版本及摘要明确。
原 30 条相关失败继续保留，任何探索性重新评分另表记录，不能覆盖原成绩。

## 4. R2：允许端点不稳定，但不能静默消耗整批任务

- 401/402 视为需要外部处理的认证/额度问题：记录当前尝试后停止发出后续任务。
- 暂态 429/5xx/连接错误使用固定次数、固定预算的退避；每次尝试均有身份、时间和结局。
  正式采集前写死具体次数和熔断窗口，不根据某一条件的成功率更改规则。
- 真实解题失败或模型长度截断不作为“端点重试”；迟到/未知请求单独标记。
- 原子保存格状态；退出时写实际退出码。独立 heartbeat 带时间戳；PID 存在也不等于
  有进展，PID 不在或 heartbeat 陈旧不能继续显示正常 running。
- 恢复验证完整候选身份，只恢复预注册允许的未完成工作；保留旧尝试，不冒充首次执行。
- 后台工作开始前固定预算、预计最大请求数/任务格数、日志位置和停止入口。

**退出条件**：模拟 401/402 后后续调用数为零；暂态错误不超过预算；强杀进程后状态能
识别中断；部分写入、旧配置和重复格不污染结果；正常恢复不重复已完成格。全部离线测试。

## 5. R3：让每个判断都能回到原始观察

- 记录 collection/cell/attempt/request 身份、格开始/结束时间、模型返回名称和可用 request id。
- 保存工具观察原文的内容哈希及受控本地副本，记录 op、错误代码、窗口和分页；敏感字段脱敏。
  运行中生成文件的读取也可按原观察复算，不再仅靠 token 数相同判断复现。
- 逐请求 usage 保留缺失状态；失败请求没有返回 usage 就标未知，不能写成零费用。
- 明确结束原因为任务完成、自然停止、轮数耗尽、completion 截断、端点错误或进程中断。
- 提供“仅观察机制重放”入口与“完整统计验收”入口，避免 630 格缺几格就无法分析已有读取。

**退出条件**：一条模拟的读→改→读轨迹可逐字重放；同 token 数不同内容被检测；生成文件
读取可复算；缺失 usage 不进入零填充平均；错误代码能定位替换失败，旧数据仍可只读查看。

先离线列出系统提示、工具定义、说明和重复文本的字符/独立 tokenizer 计数，明确这些

**退出条件**：描述含义与必要约束仍完整，输入静态计量确实减少；既有工具契约与评分

## 7. R5：收到模型后，先验证契约而非赌长跑

用户提供模型名、协议地址和凭据后，我先确认：工具调用与回传、系统/用户消息、usage、
finish 状态、超时、seed 是否实际支持。不把模型别名相似当成同一配置，不做模型 fallback。

先做最小工具往返，再固定 3 任务×A/A′/D 的九格兼容性检查。协议/运行器错误阻止进入
正式采集；合法的模型解题失败如实记录，不以“9 格必须都解对”筛选有利模型结果。
若新接口必须改变协议适配，则重新做离线契约并产生新候选身份。

**退出条件**：调用与结果可完整追溯；无未解释的协议/评分异常；失败保护可触发；预算和
超时能力有实测记录。不要求承诺全天无故障。发现认证/额度问题暂停，由用户处理入口。

## 8. R6：小规模开发比较，先判断是否值得扩大

建议预算为 **10 个开发任务 × 当前/优化 D 两版本 × 3 次调度重复 = 60 格**。
在新模型结果出现前固定任务清单、顺序和预算；覆盖语言、短/长读取、批量读取、修改和
测试反馈。这是开发样本，不是随机总体样本，也不把三个调度编号叫作独立完整研究重复。

在 task×重复内平衡两个版本顺序，记录期间错误。主指标为实际累计 usage，辅以行为
正确性、工具调用数和耗时；不把 C16 代理指标当作净收益。缺失同时报告完整配对与敏感性界。

**处置规则**：发现信息损失或恢复能力回归则拒绝候选；有安全、可重复的净收益迹象才
进入 R7；方向不清则明确“开发证据不足”，不通过换任务、加重试或挪门槛追绿。
若当前 D 已足够满足工程需求而优化价值不足，保留当前 C16 实现，停止固定开销优化支线。
