# 任务生成协议（task generation protocol）

> 目的：让「用 LLM 生成数据集」这条路**产出的数据能扛住验收**，而不是自证。
> 机器门禁：`python tools/task_admissibility.py --out eval/task_admissibility.json` → 声明 **C29**。
> 与本文件配套：`docs/acceptance-criteria.md`（什么条件下允许下结论）、`tools/task_generate.py`（生成器）。

---

## 1. 为什么要生成，以及生成**不解决**什么

**要解决的**（当前 10 任务集的真实缺陷）：

| 缺陷 | 后果 |
|---|---|
| 只有 10 个任务，且全是 30 行以内自造 fixture | 外部有效性为零；二项标准误 ≈11.3%（Terminal-Bench 89 任务是 ≈3.8%） |
| 统计功效不足 | 成功率差检出限 `\|Δ\|≥0.187`，观测只有 0.067 |
| 谓词与实现同源、改过两次（v1.2.0 / v1.3.0） | 有「把测试改成能过」的结构性风险 |

**生成不解决的**：

- 它**不**降低端点噪声、**不**改善 `len//4` 代理（那是 C27）、**不**补上缺失的提示词对照臂（那是 `docs/acceptance-criteria.md` §4.1 的 C1）。
- 它**不**把「产品缺口」变成「数据缺口」：冻结的 token ≤0.60 若点估计仍在 0.60 以上，换任务集也救不回来（除非换任务分布——而那正是**挑选数据**，见 §5）。

## 2. 独立性协议（生成阶段）

生成出来的任务若与「被测接口擅长什么」相关，就是自证。四条硬规则：

| # | 规则 | 为什么 |
|---|---|---|
| I1 | 生成提示词里**不得出现** VerseShell / ACI / typed op / observation token / 本仓库或本 benchmark 的任何信息。只给：目标语言、谓词词表、工作区形状、JSON schema | 知道接口擅长的生成器会造出接口友好的任务 |
| I2 | 任务 `prompt` **不得写出修法**，也不得逐字引用 golden diff（机器检查：A6） | 泄漏答案的任务测的是「照做」，不是「解决问题」 |
| I3 | 正确解（variants）由**看不到 golden patch** 的模型写，只给 `prompt + fixture + 谓词` | 不同实现都能过 → 谓词判的是行为而非某一种写法 |
| I4 | 至少一个 variant 来自**不同模型家族**，并记录在 `provenance.variants[].model` 与 `saw_golden: false` | 同模型的 paraphrase 不算独立 |

对抗样本（shortcuts）与任务同源生成可以接受——它的作用是**证明谓词抗作弊**，不是证明解法多样。

### 2.1 下一批的模型家族隔离（P0-2，2026-09-29）

第 14 轮冻结的 25 个生成任务，provenance.generator 全部记录为 sn-glm-5-3-flash，
与被测模型相同。旧 independent_of 只声明提示隔离；A3 的两个独立正确解不等于
任务作者独立于被测模型。现有任务不改写来源、不重新贴成异源组；这项风险尚未排除。
旧 v2 的回退调用还可能让实际作者与 generator/variants.model 不一致，旧产物不能仅凭
这两个字段证明真实作者；需要保留的原始调用证据才能进一步核验。

下一批生成前由测试方预注册两个分组的数量、语言/题型/规模组成、模型、家族来源和
留出规则。留出集必须包含非零的 cross_family 部分（或独立的公开数据集来源）；
same_family 是显式对照组，不能作为异源组。不得根据 live 结果调整分组或挑选候选。
两组分别报告 D/A 成功率差和 token 比、区间、截断及排除比例，仍遵守现有预算、
行处置和门禁阈值。新任务生成、冻结、live 对照由测试方接手，本次未执行。

v2 及 run_task_plan 的 --model 现在必填，不再继承 ACI_BENCH_MODEL。
计划必须包含 generation_policy；以下仅为格式示例，模型 ID、家族名和来源必须在
执行前替换为经过人工核实的实际值，不能把示例当作预注册计划：

```json
{
  "generation_policy": {
    "cohort": "cross_family",
    "evaluated_model": "evaluated-model",
    "model_families": {
      "evaluated-model": "family-e",
      "external-author": "family-a",
      "external-variant-1": "family-b",
      "external-variant-2": "family-c"
    },
    "family_evidence": "经人工复核的服务商模型/家族来源、别名对应关系及复核日期"
  },
  "plan": []
}
```

- cross_family：作者和全部独立解模型都必须在被测模型家族以外；模型别名按声明的
  家族归类，不能仅换一个模型名就视作异源。same_family：作者必须与被测模型同家族。
- 至少两个不同的独立解模型，均不得等于作者；至少一个解来自不同于作者的家族（I4）。
- 家族或来源缺失、分组矛盾、作者与解作者重合，均在读取凭据、调用端点和写候选之前
  exit 2。调度器遇到生成器非零退出码立即停止，不以旧准入结果掩盖失败。
- 每个角色固定使用声明的模型。允许同模型重试，失败不能切换成其他模型；候选的
  generator 和 variants.model 因此对应实际请求的模型 ID。服务端别名或底层路由
  仍需人工核实，程序不能证明服务商身份声明真实。
- provenance.generation_policy 保存分组、作者、独立解、家族来源和完整计划的 SHA-256。
  续跑与槽位计数只接受相同策略/计划指纹的候选；旧候选保留在磁盘，但不能抵充新留出组。
  修改计划意味着新批次，不能在旧计划中事后补贴来源声明。

调用示意（仅测试方在预注册完成后执行，本文不触发生成）：

```text
python tools/run_task_plan.py --plan <new-plan.json> --out <new-candidate-directory> --model <author-model> --variant-models <variant-1>,<variant-2>
```

这些校验属于生成前约束，不替代 A1–A8，也不把历史 C29 的 PASS 升级为模型家族
独立性证明。旧 task_generate.py 或自定义 --generator 不提供上述 v2 来源保证，不能
据此制作带有“已通过家族隔离校验”声明的留出集。实际冻结前必须核对计划中的
evaluated_model 与下一轮 live 的模型一致。公开数据集路线另行记录来源、版本及污染风险。

离线验证：python tests/test_task_generation_policy.py -v。负对照覆盖缺失策略、
同源伪装异源、未知家族、缺少来源、模型重合及旧候选混入；测试仅使用临时目录和
模拟 chat/run_suite，不访问模型端点、不触碰已冻结的 tasks/fixtures。

## 3. 准入判据（`tools/task_admissibility.py`，全机器判定）

候选任务放 `bench/aci/candidates/<id>/`，**通过后才允许进 `bench/aci/tasks/`**。全部用 `live_agent_loop.check_success`——与 live runner **同一个求值器**——判定：

| 检查 | 要求 | 挡住的失格任务 |
|---|---|---|
| **A1** pristine_fails | 初始工作区在谓词下**必须失败**（`False`；`None` 视为失败，fail-closed） | 已经解决/判定跑不起来的任务 |
| **A2** golden_passes | GOLDEN 覆盖后必须**通过** | 不可解的任务 |
| **A3** variants_pass | **≥2** 个独立正确解全部通过 | `file_contains` 这类只认字面写法的谓词 |
| **A4** shortcuts_fail | **≥1** 个对抗解（硬编码答案 / 只写谓词要找的字面量 / 改测试脚本）**全部失败** | 可以直接「照着谓词填空」的任务 |
| **A5** determinism | A1/A2 判定在重复执行下不翻转 | 依赖时间/随机/环境的任务 |
| **A6** no_prompt_leak | prompt 不含 golden diff 的长度 ≥12 的行 | 「照做型」任务（I2） |
| **A7** provenance | `provenance.generator` 与 `provenance.independent_of` 必须存在 | 无法追溯来源的任务 |
| **A8** large_tier_observation_size | `tier=large` 的任务，在 pristine 状态上跑谓词自己的命令（**不缩减** stdout+stderr），观察量必须 **≥1000 token** | 「自称大观察但其实很小」的任务 |

**A8 是必须的，不是可选的**：实测第一个 large 候选里，有一个按指令写了 `python -m pytest`（无 `-q`）→ 失败转储 **2627 token**（达标）；另一个写成 `python -m pytest test_textutil.py` → 只有 **231 token**（不达标）。**「large」必须是门禁，不能是愿望。** 该候选同时还在 A2（GOLDEN 根本不通过）和 A3（只有一个独立解且不通过）上失败——说明门禁确实在筛东西。

**收敛循环**：`tools/run_task_plan.py` 驱动「生成 → 准入 → 重新生成缺的」，因为单遍到不了目标：端点会 502、推理模型会输出不可解析的 JSON、生成出来的候选会被门禁拒（A2/A3/A4a/A8 都出现过）。关键点是 `task_generate.py` 把**被门禁拒绝的候选视为未完成**，否则一个坏候选会永久占住它的 plan 槽位、永远不再生成。

**`kind` 分类决定它能不能进入能力声明**：
| kind | 含义 | 能否用于能力/token 声明 |
|---|---|---|
| `capability` | 解决真实问题；除 A1–A7 外**必须**有 A4 的对抗证据 | ✅ 只有这一类可以 |
| `mechanics` | API/IO 机制（如「创建内容为 X 的文件」）。谓词天然等于交付物 | ❌ 排除；它测的是会用 API，不是会解决问题 |
| `regression` | 现有 10 任务集，保留作回归套件 | ❌ 不作为能力证据 |

### 3.1 首轮试点的真实结论（2026-09-25）

用 `sn-glm-5-3-flash` 生成 1 个 python 任务、`sn-kimi-k3` 与 `deepseek-v4.1-flash` 各写一个独立正确解，跑完整管线。结果值得记下来：

- **A1/A2/A3/A5/A6/A7 全过**：pristine 失败、GOLDEN 通过、**两个不同模型家族独立写的解都通过** —— 说明谓词判的是行为，不是某一种写法。管线本身可用。
- **A4a 失败，任务被拒**：prompt 明写「不要改 `test_batches.py`」，但**谓词没有任何东西强制它**。把测试文件替换成 `def test_trivially_passes(): assert True` 之后 `pytest` 照样退出 0 → **这个任务可以靠阉割自己的验证器通过**。它测不到任何东西。
- **LLM 对抗样本给出了误导性信号**：被要求「用最懒的方式骗过检查」的那个模型**没有作弊，而是写了一个正确实现**。所以「shortcut 通过了」这个信号**无法区分**「谓词可被钻空子」与「模型拒绝作弊」。**这就是 A4a 必须是机械检查、而 LLM shortcut 只能当参考信息的原因** —— 我最初的版本用 LLM shortcut 当门槛，它在同一个任务上给出了错误结论。
- **修复不需要改产品**：给谓词加一条 `file_contains` 守卫（引用测试文件里一行有区分度的原文），A4a 立刻通过、任务被 ADMIT。也就是说现有谓词词表**够用**，不必为它改 runner（也就避免了让整条 live 证据链作废）。
- **生成器已更新**：`tools/task_generate.py` 的系统提示现在**强制**要求这条守卫。

**这条经验的普适形式**：凡是「prompt 里说了不许做某事」的约束，如果谓词不强制，就等于没说。生成的每个任务都要过 A4a。

## 4. 组合规则（预注册，生成**之前**写死）

生成前必须定死组成，之后不许按结果调整：

| 项 | 预注册值 | 依据 |
|---|---|---|
| 能力任务总数 | **≥30** | 二项标准误从 ≈11.3% 降到 ≈7.3%；覆盖多类别 |
| 语言覆盖 | **≥3**（python / rust / typescript） | 防止「只在一种工具链上有效」 |
| 类别覆盖 | **≥4**，每类 ≥5 | 防止任务形状单一 |
| 每任务重复数 | 能力声明 **≥3**（→ ≥90 对）；token 声明 **≥5**（→ ≥150 对） | 成功率 MDE 0.15 需 45 对；token L2 需 ~122 对 |
| 能力任务谓词 | 全部为 `command_exit_0` 或含 `command_exit_0` 的 `all` | 行为判定 |
| 每个谓词 | 必须能**离线**跑（工具链在仓库内 pin 或本机已装） | 可复现 |

生成后立刻重跑 `tools/acceptance_power.py`，用新任务集的 ψ 与配对差 SD **重算**所需样本；预注册的 MDE 不变，**样本量目标可以上调，不许下调**。

### 4.1 缩小版验证轮（本轮，2026-09-25，**生成前写死**）

目的：在付 5 小时端点时间之前，先验证**管线稳定性**与**淘汰率**。因此：

| 项 | 预注册值 | 说明 |
|---|---|---|
| 候选数 | **10** | 3 个批次，混合语言 |
| 语言 | python 4 / rust 3 / typescript 3 | ts 任务的判定必须**直接跑 node**（不得要求 `npm install`/`tsc`），否则会踩 C21 记录过的工具链获取链 |
| 类别倾向 | python：解析 / 数据变换 / 状态机 / 错误处理；rust：所有权借用 / 迭代器逻辑 / 错误传播；ts：异步 / 类型收窄 / 数组对象逻辑 | 每个批次的 hint 不同，避免形状单一 |
| 任务作者 | `sn-glm-5-3-flash` | 全轮固定，便于比较淘汰原因 |
| 独立正确解作者 | `sn-kimi-k3` + `deepseek-v4.1-flash` | **两个不同家族**，都不给 golden（I3/I4） |
| 判定 | `tools/task_admissibility.py` 的 A1–A7 | 全部机械 |
| 成功标准 | 管线能跑完、失败项都有明确原因、**淘汰率被如实记录** | **不以「通过率高」为目标**——这轮是校准淘汰率，不是攒数据 |

**明确不做的事**：这 10 个候选**不进** `bench/aci/tasks/`、**不**用于任何对外数字。它们只是管线验证，所以即使全部通过也不改变任何声明。

### 4.2 缩小版验证轮的实际结果（2026-09-25）

| 项 | 结果 |
|---|---|
| 计划 → 写出 | 10 → **9**（1 次调用没产出可解析的任务 JSON） |
| 生成耗时 | **30.1 min**（10 次任务作者调用 + 20 次 variant 调用） |
| 独立正确解解析率 | **20/20**（`sn-kimi-k3` + `deepseek-v4.1-flash`，都没看到 golden） |
| 对抗样本解析率 | **2/9**（7 次不可解析）——但它只作参考信息，不判失格 |
| 准入 | **10/10 admitted**（含首轮那个已修好守卫的候选） |
| 逐项 | A1–A7 全部 **10/10** |
| 需人工复核 | 3（LLM shortcut 通过了，信号有歧义） |
| 规模 | fixture 平均 **2.3 文件 / 78 行** |

**淘汰率 0%**，但这**不是**「判据没用」的证据——做了灵敏度对照：把一个已准入候选的守卫子句剥掉后重跑，**A4a 立刻判拒**（`predicate PASSES after replacing ['test_orders.py'] with trivial stubs`）。也就是说判据确实在判别，只是生成器在系统提示里被告知守卫要求之后**学会了合规**。

**这轮真正学到的两件事**：

1. **管线可用且便宜**：10 任务 30 分钟，独立解 100% 可解析，不同模型家族的解都能过 → 谓词判行为而非写法。
2. **「扩大样本量」解决不了 token 声明的构造效度问题**（见 §4.3）——这才是重点。

### 4.3 完整轮必须改的是**任务形状**，不只是数量

实测当前定版 live 的观察规模：

| 指标 | raw_shell | verseshell_aci |
|---|---|---|
| 单次工具调用的观察 token（p50 / p90 / max） | **28 / 129 / 233** | 25 / 75 / 168 |
| 单格运行的观察 token（p50 / max） | 122 / 752 | 128 / 359 |

**观察量太小了**：p50 只有 ~25–28 token。在这个量级上，观察信封的固定开销（`ok`、`content_hash`、JSON 键名）占了大头，而 **ACI 真正要省的「大段构建/测试输出」几乎没被触发**。参照 `docs/dataset-research.md` 记录的 OpenHands 真实轨迹：**平均 64.3 轮/任务**，而本仓库任务平均 **3.2 次工具调用**——差一个数量级。

候选任务与现有 10 任务**同量级**（平均 78 行）。所以：**把 10 个任务扩到 30 个同形状的任务，只会提高功效（n），不会改善构造效度（测的是不是那件事）。** 一个在这种任务集上「通过」的 D/A 比值，可能只是在测信封开销。

因此完整轮的预注册组合必须增加**规模/形状分层**：

| 新增预注册项 | 值 | 理由 |
|---|---|---|
| **大观察任务占比** | **≥1/3**，且 raw_shell 侧单格观察 token 目标 **≥1000** | 这是 ACI 唯一可能赢的区间；不测它，token 声明没有构造效度 |
| 大观察任务的类别 | 多文件重构、依赖安装、日志分析、大文件导航、失败测试诊断 | 这些天然产生大输出 |
| 小任务保留比例 | ≤1/3 | 覆盖「小任务上信封开销是否反而更贵」这一反向问题 |
| 规模上限 | 单 fixture ≤ ~400 行、依赖必须离线 | 可复现、可判定的前提 |

**判定影响**：在加入大观察任务之前，**D/A 比值的任何结果都只能写成「小观察条件下的信封开销比较」**，不得写成「ACI 省 token」。这一点要写进报告的口径里。

## 4.4 完整轮（已启动，2026-09-25）

预注册记录：**`bench/aci/candidates/FULL_PLAN.json`**（30 条，逐条含 tier / lang / topic，写于生成之前）。要点：

| 项 | 值 |
|---|---|
| 候选数 | **30**（10 large / 10 medium / 10 small） |
| 语言 | python 12 / rust 9 / typescript 9 |
| large tier 要求 | fixture 含 **200–350 行**源文件，且 pristine 失败时诊断很长（≥8 个失败测试或等价），目标 raw-shell 单格观察 **≥1000 token** |
| 任务作者 / 独立解作者 | `sn-glm-5-3-flash` / `sn-kimi-k3` + `deepseek-v4.1-flash` |
| 定版 live 条件 | **3 臂**：`raw_shell`（中性 shell 基线）、`raw_shell_coached`（提示词等量对照，C1）、`verseshell_aci` |
| 定版 live 重复 | with 臂 **5 seeds**（→ 150 对，覆盖 token L2 的 ~122 对）；without 臂（`read_files` 消融）**2 seeds** 以控制成本 |
| 合计行数 | 30 × 3 × 5 = 450 行（with）+ 30 × 3 × 2 = 180 行（without）≈ 630 行 |

**工程前提（实测踩到的，全部是量出来的不是猜的）**：

1. **端点会间歇性 502**：第一次完整轮在 job 1 就因 `HTTP Error 502: Bad Gateway` 整体崩掉。生成器已加**指数退避重试**（4 次）并把失败降级为「跳过该 job 继续」，`provenance.plan_index` 让重跑可以**断点续跑**——一次瞬时故障只损失一个任务而不是整轮。
2. **端点约 300s 就 502**：实测一次 16384-token 生成耗时 227s 成功，而一次超过 300s 的请求返回 502。所以**单次生成必须在 ~300s 内完成**。
3. **服务的都是推理模型，会把自己的输出预算烧在 `reasoning_content` 上**——这是最硬的约束：

   | 模型 | 180 行 fixture 请求 | 结果 |
   |---|---|---|
   | `sn-glm-5-3-flash` | completion 16384 / **reasoning 16209** | 实际输出 **4719 字符**（120 行请求）；180 行请求输出 **0 字符** |
   | `sn-sensenova-6-8-flash` | 16384 / 16384 | 输出 **0 字符** |
   | `sensenova-6-8-flash-lite` | 16384 / 16384 | 输出 **0 字符** |
   | `glm-5-3-flash` | — | **502** |
   | `deepseek-v4.1-flash` | 16384 / 15067 | 5122 字符，**JSON 解析失败** |

   **结论：在这套端点上调不出「大 fixture」。** 因此完整轮的 large tier **改了机制**：观察量不再来自源码体积，而来自**失败输出**——小模块（30–50 行）+ 含 **12–18 个失败测试**的测试文件，且 pass check **不带 `-q`**，于是 pristine 的失败转储很长，raw-shell 单格观察自然超过 1000 token。

   这**不是**把要求放松：ACI 的 reducer 本来就是为了压缩构建/测试输出，所以「用失败转储制造大观察」比「用大源码文件制造大观察」**更贴近被测主张**。

4. **每次生成必须明确要求模型「立刻输出 JSON、不要长篇推理」**，否则输出为空——生成器的系统提示已加这条。

5. **单次「把整个任务设计出来」不可行；必须拆步**。这是本轮最重要的工程结论。v1 生成器要求模型一次输出「prompt + fixture + golden + 谓词」的完整 JSON，实测结果：

   ```
   finish_reason     : length
   completion_tokens : 16384      ← 整个预算
   reasoning_tokens  : 16381      ← 占 99.98%
   content length    : 0          ← 一个字符都没输出
   reasoning length  : 65460 字符
   ```

   模型的推理在「设计一个任务 + 造 fixture + 写 golden + 定谓词」这种开放式问题上**停不下来**，把预算全烧在 reasoning 里，而加预算不可行（超 ~300s 就 502）。

   **`tools/task_generate_v2.py` 的拆步方案**（每步几乎不需要推理）：
   | 步 | 要什么 | 形态 |
   |---|---|---|
   | 1 | 规格：`id / module / func / wrong` 一句话 | 一行紧凑 JSON |
   | 2 | buggy 模块、修复版、失败测试 | **代码块**（不是嵌套 JSON） |
   | 3 | 谓词 | **由程序自己拼**：命令 + 从真实测试文件里取一行做守卫 |

   第 3 步交给程序拼装，带来两个额外好处：**守卫不可能被忘掉**（v1 会出现 A4a 失败），而且**规格步也看不到答案**——独立性比 v1 更强。

   效果：实测 v1 在 large tier 上**连续多个 job 输出 0 字符**；v2 第 1 个 job 就成功产出（2 个独立 variant + 守卫），单轮成功率约 43% 并可由 `run_task_plan.py` 的多轮收敛补齐。

6. **「空回复」必须当成失败，不能当成结果**。这是第二个卡点。实测端点会返回 **HTTP 200 + `finish_reason: length` + content 为空**（reasoning 把预算吃光）。原 `chat()` 把它当成功返回，调用方拿到空字符串 → `code_block("")` → None → 整个 job 被静默跳过。现在 `chat()` 在 content 为空时**抛错并重试**。这一条不修的话，失败看起来像「模型不想做」，实际上是「预算烧完了」。

7. **测试必须写在正确实现之后（TDD 顺序），而且必须在本地自检**。这是本轮最大的质量修正。v2 的第一版顺序是 `buggy → fix → tests(buggy)`，即**测试是照着错误行为写的**，于是没有任何正确实现能满足它们——门禁上表现为 **A2 golden_passes 只有 16/31、A3 variants_pass 只有 15/31**，21 个候选被拒 16 个。**这两个分母属于第 11 轮那批 32 个候选**（当时 1 个候选缺 `task.json`，故评估 31 个）；用当前产物重算是 **A2 17/33、A3 15/33**（35 个候选，33 个被 A2/A3 评估，另 2 个缺 `task.json` 被自动拒）。**引用时必须写明是哪一批**——`eval/task_admissibility.json` 只记当前批，不复现历史批。改成：

   ```
   spec → 正确实现 → 通过它的测试 → 使它失败的 buggy 版本
   ```

   并且在**写入候选之前本地自检**：测试必须在正确实现上通过、在 buggy 版本上失败、每个独立 variant 也必须通过。自检不过就跳过该 job，而不是把不一致留给门禁去发现。

8. **large tier 的测试数量要按端点能力收窄**。要求 12–18 个测试函数时端点反复返回空回复；收到 **8–12 个测试、每个断言多个值**后可行——失败转储仍然够长（A8 会实测确认，plan#1 曾达 2627 token）。

9. **端点能力是时变的，所以每一步都要「跨模型轮换」而不是「同一个模型重试」**。实测同一个「给这个模块写测试」的请求：单独探测时 5 个模型**全部**成功（1599–2485 字符，都带代码围栏）；但在流水线里同一请求对 `sn-glm-5-3-flash`、`sn-kimi-k3`、`deepseek-v4.1-flash` **连续全部返回空**。同一时刻的健康探测（小请求）却是 **0/5 空、15–23s、~850 字符**。结论：

   - 空回复与**请求规模**强相关（小请求稳，大请求不稳），也与**时刻**相关；
   - 因此 `step()` 改为**依次尝试多个模型**，任一成功即用；重试同一个模型只是浪费几分钟；
   - 独立性不受影响：variant 的候选池**排除任务作者**，即使走到 fallback 也仍是别的模型写的。

10. **每一步都要本地自检，而且自检要能重试该步**。实测过两种被自检拦下的情况：①「给正确实现写的测试」在正确实现上不通过；②「引入的 bug」**没有**让测试失败（模型改的地方测试根本没覆盖）。两者都在写入候选前被拦住并重试该步，而不是留给门禁去发现。

## 4.6 第 14 轮：难度与大观察占比（**预注册**，2026-09-27 / tree-farm TF-0114）

> **写这条时第 14 轮 live 还没有跑，也没有任何第 14 轮的任务级结果。** 本节的全部数字都是**目标**，不是测量。

**为什么必须动难度，而不是加样本**：第 13 轮 A / A′ 的成功率**都是 0.8400**，到 1.00 只剩 **0.16** 的可用余量，
而预注册的 MDE 是 **0.15**——`MDE / 可用余量 = 0.15 / 0.16 = 94%`。
这意味着在固定的观测基线0.84下，预注册的+0.15正向效应已接近最大可能提升0.16。
增加 n 可以缩小区间、帮助检出更小效应，但不能把固定基线对应的最大正向提升抬高；
不能据此断言更小正向效应或负向差异“结构上不可检测”，也不能把一次观测基线当作未来总体真值。

**预注册目标（第 14 轮任务集 = 当前 15 + 本轮补齐 15 = 30 生成 + 10 既有 = 40）**

| 项 | 目标 | 判定方式 | 理由 |

| `MDE / 可用余量` | **≤ 0.50** | `0.15 / (1 − 基线成功率)` | 直接给出「天花板还剩多少」 |
| large tier 占比 | **≥ 1/3** | 每个任务在 pristine 状态下的裸 shell 观察 ≥1000 token（A8 的同一判据） | 第 13 轮只有 **16%（4/25）**，token 声明的构造效度弱（§4.3、§4.5） |

## 4.6 下一轮组合目标（预注册，2026-10-10）

**目的**：把 large 观察占比、语言/题型配额和异源来源写成看数据之前的目标，避免再按第 14 轮 token 结果补题或只补 30 个槽位。

**分母与目标**

- 分母是**最终冻结任务集**：既有手写任务 + 新生成并实际准入的任务；不得只拿生成子集或旧标签算比例。
- large 的定义仍是 A8：`tier=large` 的任务在 pristine 状态运行谓词自己的命令，不做输出缩减，`len(normalised_dump)//4 >= 1000`。未测任务不得默认为 small，也不得用源码行数替代。
- large 配额为 `L / N >= 1/3`，因此最小 `L = ceil(N/3)`；成功率和 `MDE/可用余量` 仍按 §4.5 的预注册目标，不由 large 配额反推。

**当前基线与补充算式**

- 当前 35 个任务中，有 A8 证据且达标的只确认 **7 个 large**；其余 28 个不能默认为非 large。
- 若保留这 35 个任务并只新增 `x` 个全部通过 A8 的 large 任务，则需 `(7+x)/(35+x) >= 1/3`，即 `2x >= 14`，最小 `x=7`。
- 若按“补齐原计划 5 个 large 槽位”的方案，则最多得到 `12/40=30%`，仍不达标；必须至少再增加 2 个经验证的 large 任务才有 `14/42=1/3`。因此目标定为新增 **至少 7 个 large**，而不是只补 5 个。
- 最终数量、语言组成和留出比例须在生成前由测试方预注册；上述 7 是当前证据下的最小数学缺口，不得在看到 token 结果后下调。

**观察机制（只适用于未来批次）**

- Rust large 使用 `cargo test --no-fail-fast`；每条失败用例保留真实长 payload，禁止只比较长度/计数或增加填充日志。
- TypeScript large 使用 `node --test --test-reporter=tap check.mjs`；每个用例独立注册，失败继续收集，断言长载荷必须来自真实行为差异。
- 统一 12–18 个独立用例；A8 按实际输出判定，测试数量不是观察量或难度的证明。
- 生成器本地验证和 A8 读取都走二进制 `run_bounded`，按与 raw-shell 一致的 UTF-8/OEM 解码；超时为 unknown，不判 large。

**来源与冻结**

- 新批次按 §2.1 的 `generation_policy` 预注册；`cross_family` 留出集必须非零，`same_family` 只能作显式对照。
- 生成前固定任务数量、语言/题型/规模组成、作者/变体家族、拒绝规则和留出规则；未知家族不进入正式能力/泛化主张。
- 一旦看到本轮任务的 D/A token 结果，不得按结果增删任务、改 tier 或改 A8 门槛。

## 4.7 第 14 轮任务集的**实际**结果（`task_set_version = 3.0.0`，冻结于任何第 14 轮 live 结果之前）

**预注册 30 个生成任务，实际准入 25 个；补齐的 15 个槽位里 10 个成功、5 个未成功。**

| 项 | 预注册目标 | 实际 | 差额 |
|---|---|---|---|
| 任务总数 | 10 手写 + 30 生成 = 40 | **10 手写 + 25 生成 = 35** | **−5** |
| 语言（生成任务子集，实际25个） | python 12 / rust 9+ / typescript 9+ | **python 12 / rust 6 / typescript 7** | rust −3、ts −2 |
| 已确认 large 观察占比 | **≥ 1/3** | **7/35 = 20%**；A8产物只覆盖25个生成任务，另10个手写任务未覆盖 | **现有证据不能保证配额达标，不把未覆盖当作已测small** |
| 留出集（从未参与调参） | ≥10 | ✅ **10**（本轮提升的那一批，见 `eval/task_set_freeze.json` 的 `holdout`） | — |

**未补齐的 5 个槽位全部是 `large`**：rust 5、6、7 与 typescript 9、10。它们不是生成不出来，而是**反复卡在 A8**——
A8 要求 `tier=large` 的候选在 pristine 状态下的裸 shell 观察 **≥1000 token**，而这 5 个槽位的候选实测集中在
**277–590 token**（同批的 python large 却轻松达标：`python_nested_flatten` 3496、`python_csvlite_parse` 1559）。

**为什么恰好是 rust 与 typescript 的 large 失败（两条结构性原因，都已观察到）**：

1. **typescript 的失败转储被运行时截断**：`check.mjs` 由 plain node 执行，第一条断言抛出就终止进程，后面 11–17 条失败
   测试的 diff **永远不会打印**。python的pytest会继续收集失败；Rust默认cargo test只保证单个测试二进制内继续运行，失败后可能不再运行integration test目标，
   所以同样的"12–18 个失败测试"在 ts 上只产生一条失败的输出。
2. **Rust默认在失败的测试目标之后停止**：本次核查的四个候选都有短的库内测试和较长的integration tests。默认cargo test在库内失败后停止，后一个测试二进制未运行；不能仅将277–590 token归因于“Rust摘要天生短”。

**这两条是本轮实测到的构造限制，不是"再跑几轮就会好"**：本轮为此把 large 档的测试数指令从 3–5 个提高到
**12–18 个**（对齐 `FULL_PLAN.json` 的 `large_tier_requirement`），python 立刻达标，rust/ts 仍不达标。
要真正达标需要改的是**观察机制**（例如 ts 用测试框架而不是裸 node、rust 让每条失败都打印长 payload），
那是产品侧改动，必须重新预注册，**不得在看到第 14 轮结果之后再改**（§5）。

**同时修掉的生成器缺陷（5 条，全部是本轮实测抓到的，不是推测）**：

1. **模块名未净化**：spec 步偶尔把路径当模块名返回（`src/lib.rs`），被直接写进 `Cargo.toml` 的
   `name = ...`，导致该槽位的 3 次测试尝试全部编译失败后整槽被跳过。现在取 path stem 并净化成合法标识符。
2. **correct 模块没有独立的编译闸门**：模块本身被截断（悬空 doc comment → `error: expected item after doc comment`）
   时，生成器会连烧 3 次**测试**尝试才放弃，而模型从未被告知是**模块**坏了。现在先用一个最小 smoke 套件验证
   correct 模块可编译/可导入，失败就重生成模块。
3. **variants 与 task.json 分家**：`variants/` 目录先被创建，使随后的 `if cdir.exists()` 分支把 `task.json`
   写到 `<tid>_<seed>/`，于是 A3 看到 **0 个 variant** 而拒掉本可通过的候选（`python_spiral_order_*`、
   `python_cronfield_*` 就是这样死的）。现在候选目录在写任何东西之前就定好。
4. **rust 的 variant 路径没建父目录**：`src/lib.rs` 的父目录不存在，直接让整个生成器进程
   `FileNotFoundError` 崩溃（一次崩溃 = 整轮白跑）。
5. **`tools/run_task_plan.py` 的槽位计数假收敛**（最危险的一条）：它统计**所有**候选的 `plan_index`，从不与
   当前计划求交，所以 15 槽计划里被算进了 FULL_PLAN 的 5 个槽，`absent` 一度是 **−19**，并在只剩 10/15 时
   打印 **"all 15 plan slots have an admitted candidate"** 后以 exit 0 退出。现在按**槽位**统计
   （同槽位只要有一个准入候选即算覆盖）并与计划求交。**上面这张"实际 25/30"的表就是用修好的计数器重算的。**

## 4.8 配额算术与难度证据的分离（P2-2修复核查，2026-09-29）

当前自动审计：`python tools/task_design_audit.py` → `eval/task_design_audit.json`。
它不选择任务、不改生成提示，不向生成模型提供任务级live结果。

- 标签与实测不是一个数：冻结元数据的large标签为4；准入产物覆盖25/35个任务，
  其中7个pristine观察达到A8的1000代理token。其余10个没有这份测量记录，不能默认为
  已测small，也不能据此断言真实large比例恰好是20%。
- 若保留35个任务、只使用现有7个已确认large，并追加x个且都实际通过A8，则
  `(7+x)/(35+x) >= 1/3`，即 `2x >= 14`，最小x=7。
  只补5个时，已确认比例为12/40=30%；再补2个才是14/42=1/3。
  这是“不重新确认原有未知任务”的保证方案，不是所有可能方案的最小任务数。
  未覆盖任务如经独立、预先定义的测量补齐，所需追加数可能下降。
- 当前A的95/105只是本轮观测基线；固定这个基线时正向余量为10/105，小于预注册MDE=0.15。
  不能把这句话扩展成“任何成功率差都检不出”。目标0.40–0.70和MDE均不变。
- 新难度设计必须交给没有看到任务级live结果的作者，预先固定题型、配额和留出规则；
  观察量和解题难度分开设计，不能把延长失败输出当作已经加难。
  本修复会话已经接触了结果，因此只修审计/算术/报告，不声称完成了盲设计。

本审计纳入重刷链和C12新鲜度检查；未知、冲突或跨冻结版本的数据不能被选择性拼接成达标。
实际新任务、A基线落入目标区间及留出集live效果，仍由测试方完成后才能验收。

## 4.9 large候选的完整失败观察（P2-3，2026-09-29）

仅适用于未来预注册批次，原冻结任务及原候选不改写。

- large Rust使用 `cargo test --no-fail-fast`，避免失败的库测试遮住integration tests；新测试要求比较完整、有意义的长集合，而非只比较len/count。
- large TypeScript使用 `node --test --test-reporter=tap check.mjs`。每个用例用node:test注册，断言在各自回调中；禁止把所有失败函数在模块顶层顺序调用。断言比较完整长载荷，不添加填充日志或重复转储。
- 统一12–18个独立用例的既有要求，删除TESTS_SYSTEM中冲突的3–5个要求。测试数量本身不是观察量或难度证明，A8仍按实际输出>=1000代理token判定。
- 生成器本地验证和A8读取统一走二进制run_bounded，再按与raw-shell一致的UTF-8策略解码；超时为未知，不能用不完整输出判large。

同五个被拒候选的临时副本成对验证（相同MSVC/Node环境、相同断言值）：

| 候选 | 原运行机制 proxy token | 全量运行机制 proxy token | GOLDEN |
|---|---:|---:|---|
| rust_primesieve | 277 | 1961 | PASS |
| rust_chunker | 391 | 2104 | PASS |
| rust_sliding_sums | 442 | 1933 | PASS |
| rust_spiral_order | 590 | 2325 | PASS |
| js_csvlite_parsecsv | 394 | 3537 | PASS |

Rust新增运行的integration目标分别报告15/14/15/18个失败；TS原18个用例全部注册，报告7个失败。
A8大小检查从0/5变为5/5，**不是完整准入**，也不是live效果证据。原候选仍可能缺少独立variants等证据，不能据此提升。
此前“手工收集包装只得到665 token”的结果只适用于那个包装，不能推导所有完整报告机制都不足。
本探针没有增加断言载荷；新生成器仍明确要求真实长载荷，并由A8实际把关，不以测试条数替代。

## 5. 冻结规则（最重要的一条）

**任务集必须在测量之前冻结，并写入指纹。**

- 一旦看过某个任务集上的 D/A token 比，就**不得**再按该结果增删任务、调整难度分布或改谓词。
- 允许继续生成的唯一时机是：**在看不到 token 结果的前提下**按 §4 的预注册组合补齐配额。
- 换任务集后旧数字**全部作废**（C12 的指纹覆盖 `bench/aci/tasks/*.json` 与 `bench/aci/fixtures/**`，机器会判陈旧）。

理由：`≤0.60` 这个冻结目标是**数字**。如果任务集可以按数字调，那就变成在任务分布上做搜索——这正是「挑选数据」。当前 0.7794 是**在旧 10 任务集上**的结论；新任务集上重新测出的点估计**可能更好也可能更差**，两者都必须在冻结后照实登记。

## 6. 溯源与许可

外部导入或生成的每个任务都要带上：

```json
"provenance": {
  "generator": "<model id>",
  "generator_role": "task_and_golden_author",
  "independent_of": "<说明生成时没有提供哪些上下文>",
  "variants": [{"model": "<model id>", "role": "independent_correct_variant", "saw_golden": false}],
  "source_url": "<若来自外部仓库，必填>",
  "source_version": "<commit / tag>",
  "license": "<SPDX>",
  "generated_at": "<ISO8601 UTC>"
}
```

从公开仓库导入真实 bug（SWE-smith 式「回退修复提交」）时，`source_url` / `source_version` / `license` **必填**，且许可必须与源仓库一致（见 `docs/dataset-research.md` §5.3 第 9 条）。

## 7. 禁止清单（判失格）

| 禁止 | 原因 |
|---|---|
| 生成器看到 ACI/benchmark 上下文 | 自证 |
| prompt 里写出修法 | 测「照做」而非「解决」 |
| 只用 `file_contains` 这类字面谓词当能力任务 | 只认一种写法；且可照抄 |
| 没有对抗样本就标 `kind=capability` | 谓词是否抗作弊未被证明 |
| 按 token 结果增删任务 | 在任务分布上搜索 |
| 用 `mechanics` 任务撑能力声明的样本量 | 谓词等于交付物 |
| 把同模型的 paraphrase 当独立 variant | 不是独立证据 |
| 跨任务集版本直接比数字 | 分母不同（C21④/C13⑫） |

## 8. 代价（照实说）

| 环节 | 成本 |
