## 本批根因修复

1. **TF-0122：合并证据与持久化。** 原合并器解析输入后重新读文件取摘要，可能让旧行配上新文件的摘要；直接覆盖结果还会在写入故障时损坏旧产物。现在从同一份原始 bytes 解析并计算摘要，发布前复核输入未变，使用既有 `live_journal.atomic_json` 提交；拒绝输出与输入同路径或同文件硬链接。源变更、删除、读取失败、ENOSPC 均失败且保留原输出。
2. **TF-0133 相关入口：禁止参数缩写绕过。** 控制器只拒绝完整 `--publish/--dry-run/...`，子解析器却默认接受 `--pub/--dry-r/...`，dry-run 还有错标 completed 的风险。三个现有 argparse 解析器统一 `allow_abbrev=False`；完整参数与 report-only 路径保持原行为，不引入新分发层。
3. **TF-0137/0141：源码冻结清单完整性。** 独立克隆的首轮完整验收发现评分 CLI 沿用了 HEAD 的旧版，因为 `source_hashes` 漏了 `bench/aci/scorers/score.py`。该旧版会接受历史 live PASS。现在将评分脚本纳入同一清单，并让 `verify_readiness` 比较完整当前清单，拒绝遗漏、额外项或摘要变化，而不只遍历调用者给出的项；`claim_sources` 复用此清单，也同步获得覆盖。
4. 上一批七文件报告清单修复完整保留，本批备份基于包含该修复的脏工作区，不是 HEAD。
