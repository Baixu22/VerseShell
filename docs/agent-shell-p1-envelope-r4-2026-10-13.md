与同设计旧轮 `p1-20261012-r3` 做自对比。

## 1. 为什么是本轮

- 上一轮 `recover-r1-20261013`（6 道最难题子集）判 INVALID：2/18=11.1% 预算耗尽，且 A′ 方差达 ±33pp，n=6 不可归因。
- 本轮回到 handoff 的**预注册主设计**：T01–T10 全跑，30 格一次完成，≤12 tasks / ≤60 cells / ≤2h。
- 预算与旧轮完全一致（12 calls / 240s / 4096 tokens），**只换 treatment**（新 ae 二进制），因此可比。
- 新 ae sha256：`12b427a96cfc284e955a0274bdad5753b4a7e29c384db2f77d0c8b66885004eb`
- 旧 ae sha256：`64c59cbf82b875abfc344e255d68989486e159beb136b1271e2d59729bfdbc78`

## 2. 内存自适应（沿用 r1 的闸门）

- 1 vCPU / 512 MiB sandbox，**串行**一次一格；每格前等待宿主可用内存 ≥ 1200 MB；cell 间 8s 冷却。
- `run_round.py` 也用上了闸门；cell 内记录 `host_memory.available_mb_before / after_close`。
