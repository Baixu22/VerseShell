## 额外定位并修复的问题

1. C24 打印 FAIL 仍退出 0：现在失败或空审计返回 1，刷新链可中止。
2. C24 门禁信任 report 的 `pass`：现在核对所选版本、全部 GOLDEN 任务覆盖及实际评分谓词。
3. Job 创建和绑定存在 64 位句柄参数/返回值问题，且泄漏句柄：已纳入 D8 根因修复。
4. `cap_excluded` 只排除 turn cap，没有排除 completion 截断：已补齐，并增加跨臂计数回归。
5. 正式共享统计只输出 `ratio_of_sums`：增加并列 `mean_of_ratios`、任务聚类区间、配对权重与零分母排除数量；原总量估计保留。
6. 自定义输入报告只指纹 canonical 默认路径：新增实际输入文件 SHA256，记录来源/模型/任务集。
7. Holm 缺区间的效果项被保留为可主张：现在 fail closed，并计入家族规模；C36 同样拒绝未通过校正的效果主张。样本量功效项明确是设计诊断。

## 尚未关闭的短板

1. **修复后的外部效果**：全部旧 collection 的 runner 指纹已不适用于当前树；需要新采集。
2. **因果归因**：有 compact_all 实现不等于因果检验完成。应匹配 baseline 与 compact_all 的模型、任务、预算、种子，顺序运行，再比较处理交互。不同接口必然有不同工具集合，不能宣称所有文字完全相同。
3. **困难任务与覆盖面**：35 题的 shell 成功率已接近满分，正向 +0.15 MDE 缺空间。新任务需独立作者/盲评、行为判据、GOLDEN/负控、准入与冻结；不能用已有模型失败名单定制验收集。
4. **重复性**：3 seed 是一次工程采集的分片，不是独立重复；以后需独立轮次，报告运行间波动。
5. **消融与身份**：当前没有 without 臂；relay 别名不提供稳定底层模型版本。Step 5 P 需登记精确 model id、端点、协议及服务方能提供的版本信息。
6. **统计边界**：缺失的成本/成功效果区间保持不可主张；当前 Holm 使用 CI 近似 p 值，不能包装成精确检验。新逐任务区间尚不属于预注册确证家族。
7. **进程与外部中断**：Job 绑定发生在 Popen 后，极短启动窗口仍存在；Job 不可用时不承诺后备工具绝对可靠。c21 的外部终止来源未证明，本次不把看门狗视为根因修复。
8. **完整产品验收**：本次没有重跑 Rust 全项目、跨 shell 墙钟、完整 claim gate 或真实端点；Python 通过不能替代这些验收，也不关闭历史 C14/C16 门槛缺口。
