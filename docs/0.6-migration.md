# Migrating to VerseShell 0.6 Operations (0.6.1)

VerseShell 0.6 keeps the legacy `cmd` JSON-RPC request and the MCP `exec`/`eval`
tools for the entire 0.x series. New Agent integrations should use typed
operations because they provide stable schemas, bounded observations, and raw
output recovery.

## JSON-RPC

Legacy:

```json
{"id":"1","agent":"coder","cmd":"shell.exec([\"cargo\",\"check\"])"}
```

Preferred:

```json
{
  "id":"1",
  "agent":"coder",
  "op":"exec.run",
  "args":{"argv":["cargo","check"],"cwd":".","profile":"auto","artifact":"auto"},
  "timeout_ms":30000,
  "budget":{"max_tokens":4000}
}
```

Non-zero process exits return `ok:false` and `error.code:"E_PROCESS_EXIT"`, but
the response still contains stdout, stderr, diagnostics, and artifact handles.
Timeouts use `E_TIMEOUT`; spawn failures use `E_EXEC_NOT_FOUND` or
`E_EXEC_SPAWN`.

## MCP

- Replace `exec` with `exec_run` when invoking an external program.
- Use `result_query` with `meta`, `head`, `tail`, `slice`, or `grep` before
  requesting `raw`.
- `raw` is explicit, limited to 1 MiB per call, and remains subject to the
  observation token budget.

## Output semantics

- `full`: complete model-visible text.
- `empty`: successful stream with no content.
- `reduced`: a command-aware summary; raw output is referenced by artifact.
- `truncated`: bounded head/tail view; omitted bytes are explicit.
- `binary`: no text interpretation; inspect the artifact explicitly.

Artifacts live in `<workspace>/.ae/results`, are content addressed, expire after
24 hours, and are capped at 512 MiB per workspace. Artifact contents are never
written into the audit log.

## v0.6.1 observation quality

0.6.1 is a non-breaking observation polish over 0.6.0. Operation names are unchanged.

### Success silence

For auto-detected noisy commands (`npm install`, `cargo build|check|test`,
`pip/uv install`, `pytest`, `msbuild`/`dotnet`):

| Field | Contract |
|-------|----------|
| `status` | `reduced` |
| `summary` | short final outcome (<=120 tokens, <=4 lines) |
| `text` | omitted |
| `artifact` | present under `artifact: auto` so raw logs remain queryable |

Progress lines (`Compiling ...`, reify noise, download spam) are not model-visible.

### Failure focus

On non-zero exit or timeout:

- Model-visible `text` is a **failure window** (error/failed/panic blocks +/- context), not the whole log.
- Full stdout/stderr bytes remain in the artifact.
- `diagnostics` lists structured error lines when parseable.
- `suggested_next` recommends `result.query` with a profile-aware grep pattern.

### Preprocessing

- ANSI/CSI color sequences are stripped before reduce/truncate.
- Consecutive blank lines are collapsed.

### Profiles

| Profile | Auto when argv is... |
|---------|----------------------|
| `npm_install` | npm/pnpm/yarn/bun `install|i|add|ci|update` |
| `cargo` | cargo `build|check|test|clippy` |
| `python_install` | pip/uv/poetry install/add/sync |
| `pytest` | pytest |
| `msbuild` | msbuild / dotnet |
| `git` | git (large status/diff/log reduced or truncated) |
| `generic` | everything else |

### Compatibility

- `exec.run` / `result.query` schemas are unchanged.
- Legacy `cmd` / MCP `exec` remain available for the 0.x series.
