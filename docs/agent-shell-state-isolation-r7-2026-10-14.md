# 运行时状态隔离 + recourse 去占位，L4 纵向 r7（2026-10-14）

本轮继续"吸收功能但避免过度设计"，只做有数据支撑的两项，并明确否掉一项无证据的。

## 1. 本轮改动

| # | 改动 | 依据 |
|---|---|---|
| **F1** | 失败 recourse 改为回放**真实 argv**：删掉 `echo retry-with-larger-timeout`、`ls -l`、`command -v sh; ... echo check-missing-tool` 三个占位命令 | 设计文档自述"占位动作稀释真建议"；实测 20 条 suggested_next 被照抄执行 **0** 条 |

| — | 控制字符折叠：**不做** | 562 次观察 / 381K 字符里 `\r`/`\b`/NUL 出现 **0** 次 |

## 3. F2 的实际效果（关键测量）

| 轮次 | 状态位置 | D 总调用 | 自侦察调用 | 占比 | 涉及 cell 数 |
|---|---|---:|---:|---:|---:|
| r6 | 工作区内 | 264 | 52 | 19.7% | **17 / 20** |
| r7 | 工作区外 | 288 | 50 | 17.4% | **2 / 20** |

即：**系统性的"发现 `.ae` 就去翻"消失了**（17 格 → 2 格）。剩下 2 格（T413、T420）是模型主动 `find / -name '*.json'`、`strings /usr/local/bin/ae` 找出来的——
这是"难题失败后乱翻"，不是工作区泄漏。绝对调用数只降 2 次，是因为这 2 格的搜索量很大。

## 5. 诚实结论

1. **F2 机制上成功**：运行时状态不再出现在 agent 工作区，系统性自侦察从 17 格降到 2 格，artifact/`result.query` 不受影响。
2. **F1 无行为证据**：把占位命令换成真实 argv 更诚实、可回放，但实测本就 0 采纳，故不会改善指标——它是"去装饰"，不是增益。
3. **L4 裁决没有变好**：r7 D 与 A prime 打平（16/16），obs 比反而升到 2.34x。
   原因是两处 heavy-tail（T413 40 次调用 / T420 72 次调用，合计占 D 全部调用的 39%）把均值拉坏。
4. **五轮合并看**：D − A prime = +5 / −5 / +5 / +5 / 0 pp。方向偏正但**只有 +1 题量级**，仍不足以称为稳定效应。
5. **效率门槛依旧不可达**：obs 比在 1.67x–2.34x 间波动，对照臂自身跨轮摆动 ±38%，单 seed 无法支撑 −20% 判定。

## 6. 诚实边界

- 单 seed、单机、诊断级；+5pp = 净 +1 题，二项 sd≈1.9 题。
- r7 的 T410/D 是 **sandbox 启动失败**（microVM 未起来，ae 未运行，0 tool_calls），属环境瞬态，非代码缺陷。
- r3→r7 跨轮次，ae 二进制与预算均变化；已逐轮标注。
- 未提交 / 未合并 / 未推送；未改 Task Forest；全部旧轮与失败样本保留。

## 7. 下一步建议

1. **多 seed** 才能把 +1 题量级与噪声分开（3 seeds × 60 格）。
2. **heavy-tail 治理**：T413/T420 两格吃掉 39% 的调用，建议单独分析失败模式，而不是继续调信封。
3. **停止在成功路径上继续裁剪**：已验证 stream 元数据只剩 3–5 个键，剩余体积主要是 stdout 正文（49.4%），需要内容级规约才可能显著下降，属产品行为改动。
