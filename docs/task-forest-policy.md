# 本工作区 task-forest 工作策略（根策略）

> 适用范围：本仓库（VerseShell）所有后续开发会话。
> 优先级：**高于 task-forest skill 的默认「等待用户确认」规则**。skill 与本文件冲突时，以本文件为准。
> 变更方式：改本文件 + 在 task-forest 里更新对应 decision/requirement 节点（两者必须一致）。

## 1. 角色分工

| 角色 | 职责 |
|------|------|
| 用户（发布者 publisher） | 只做发布/对外动作与方向确认；**不是**开发主线执行者 |
| agent（开发主线） | 规划、实现、验证、证据登记、森林收口，全部由 agent 闭环 |

因此 agent **不得**把下面这类问题变成「问用户」：实现方式、口径选择、阈值数字、命名、文件位置、是否 apply 提案、进度怎么记。这些一律由 agent 决策并在仓库里留下理由与证据。

唯一允许提问的情况：**需求本身指向不明**，且无法从仓库文件、`docs/`、task-forest 历史与既有决策推断。此时只问一个最小问题，其余部分继续推进。

## 2. 提案即执行（替代人工确认门）

- 图变更**仍然必须**先 `proposal-save`：保留 `base_graph_hash`、事件流与快照，供第三方审计与回放。
- 证据链完备时**立即**执行 `proposal-apply --yes`，随后 `validate`、`export`；**不等待用户确认**。
- 唯一例外：提案所依赖的图已被其它 session 改动导致冲突，且无法自动判定 → 重新读取 `list --json` / `todo --json`，按最新图重算提案后应用；仍然不问用户。
- 禁止把「等用户点确认」当作进度停滞的理由。

## 3. 自动 done 的四条硬门槛

节点可自动转 `done`，当且仅当四条全部满足：

1. `acceptance_criteria` 逐条有**可复现证据**：命令 + 输出摘要或文件路径 + 日期；
2. 涉及对外数字的，已登记在 `docs/claims-and-evidence.md`，且 `python tools/claim_gate.py` 退出码为 0（或该声明显式标注「不设门槛」并写明失效边界）；
3. 相关门禁与测试全绿：至少 `python tools/claim_gate.py`；改动 Rust 代码时加 `cargo test`；
4. 证据回写进 forest 节点的 `evidence` 字段（**不是**只写在对话或日志里）。

不满足时：节点保持 `in_progress` / `ready`，把缺口落成新的 `follow_up` 节点（带来源证据），继续推进，**不问用户**。

## 4. 自圆其说（第三方可审计）

- 每个结论都要能被第三方只读复现：数字有命令、判断有 source、结论有「失效边界」。
- 未证实的声明标 `未证实`，不得以肯定口吻进 README。
- 口径冲突时取**更严的一侧**，并在文档写清选择理由；不允许两处文档各说一套。
- 里程碑（milestone）在其全部子节点 done 后自动收口；`global_task` 只有在全部 desired_outcomes 都有证据时才 done，否则留 `in_progress` 并写明剩余缺口。

## 5. 非阻塞例外（只说明，不阻塞主线）

不可逆或越界动作：改写 git 历史、`force push`、删除分支或数据、跨仓库外发、大规模付费 API 调用。

处理方式：先做安全等价步骤，在最终报告里**点名该动作与影响**，然后继续主线；不把它做成等待回答的问题。

## 6. 每轮收尾固定动作

1. `proposal-save` → `proposal-apply --yes` → `validate` → `export`；
2. 报告中给出：提案路径、HTML 路径、本轮节点状态变化、门禁命令与结果、遗留缺口对应的节点 ID；
3. 发布（publish/部署）是用户动作，不作为任何开发节点的前置条件。

## 7. 工具链边界（哪些进版本库）

| 内容 | 进版本库 | 理由 |
|------|----------|------|
| `.agent-workbench/task-forest/`（图、事件流、快照、提案、导出） | 是 | 第三方审计与回放需要 |
| `proposals/`（提案可读副本） | 是 | 与森林内提案一一对应 |
| `tools/*.py`（`claim_gate` / `jev_obs_judge` / `validate_manifest`） | 是 | 验收门禁必须能被 clone 后直接跑 |
| `eval/`、`examples/`（指标、探针、复现入口） | 是 | 声明的 source 与复现命令 |
| `.mimocode/skills/task-forest/`（森林 CLI 本体） | 否 | 本地工具安装，可重装；规则源以本文件为准 |
| `.trae/`、`.ae/`、`target/`（编辑器笔记、运行期产物） | 否 | 本地草稿与缓存 |

`.gitignore` 的 `*.py` 规则原本是一次性清理脚本的历史遗留，已用 `!tools/*.py` 精确放行门禁脚本；**不要**再整体放开 `*.py`（会把本地工具与草稿一起卷进版本库）。
